## 正常链路

每版每组只运行一次，使用相同项目配置、模型与运行预算。先完成基线，
再运行候选；记录精确提交和配置摘要，不输出凭据。每一步：

1. 正常导入该步消息，保存返回的 Operation、Blob 和 Source 身份。
2. 沿原 Operation 查询 Fact 完成回执；超时／未知不重发正文。
3. 等待正常自动 flush，读取 Fact、Profile、Event 及其有效支撑。
4. 有后续导入／删除时沿原身份继续，保留每一步的读取结果。
5. 验收完成后走正常用户删除，核对清理结果。失败结果同样保留。

不直接造 Fact，不篡改工具输出，不注入故障，不重复生成直到通过。
发生阻塞时记录原状态，不能跳过该步给后续步骤判通过。

## 人工评分及记录

逐组逐步判断 `must_preserve`、`must_not` 和 `acceptable_variations`。
分别列出 Fact、Profile、Event 的实际 ID、支持组、结论和缺口；删除后
先检查 Fact，再检查 flush 后派生结果。语义允许拆分、合并和不同措辞，
但主体、原因、时间、确定性和证据必须对应。不能以数量、HTTP 成功、
JSON 合法或关键词匹配替代人工结论。

Fact 验收的是有消息支持的历史陈述；Profile／Event 验收的是根据这些陈述、事件时间和
明确更正整理出的理解。同批或跨批的直接陈述与后续更正可以同时保留，不能仅因两者
冲突就判旧 Fact 错误，也不要求给每条旧直接陈述追加“已更正”限定。派生结果仍须识别
更正，不能把旧说法继续呈现为当前结论。原文只有“我告诉 Ellis，P”时，保存的是告知及
其内容，不能升级成 P 确实发生；这与用户直接陈述 P 后再更正是不同的证据范围。

fact_time 按所记录事件或状态的含义及原文时间证据判断，不机械绑定句首“说／回忆／
更正”。正文表达更正后的经历时，可以使用有依据的经历日期；正文专门记录告知行为时，
才使用有依据的告知日期。担忧、不知情等不继承其对象日期；无法从正文判断所记录事件
时列为语义歧义，不仅凭句首动词判错。

动作状态检查区分“打算／尝试／已经完成／取消”，拆分后仍须保留原文明确的同次经历
关联。证据检查逐组遮去组外消息：正文中的姓名、代词及限定是否仍成立；不能靠组外
身份或另一组证据补全。身份前提删除、具名独立确认及时间支撑分别验证；不要求
无日期的独立组证明日期。维护后的标题、摘要和正文使用一致的状态，不能猜补 Fact
遗漏。MockTransport 只证明传递和校验，以上语义必须用真实首次结果核对。

属性未说明时应保持中性，有明确依据时仍须保留。支持组既要充分，也不能绑定无关
上下文；助手消息是否必需取决于用户确认或指代，不按角色一概排除。Profile 精简后，
有效经历细节仍须保留在 Fact／Event 中。不能以条目变短判定信息质量改善。

主体与确定性按正文的主断言检查：用户表达担忧／不知情时，主体是用户，asserted
不表示被担忧的情况已经证实；若正文主断言是某人可能处于某状态，则该人是主体、
certainty 为 uncertain。转述保留报告来源。支持组逐条做删除检验：移除仍能完整证明
结论的上下文，不移除身份、选项或否定等必要前提。关系画像保留跨会话有持续价值的
属性和关系，而不是近期状态与临时担忧的事件摘要；持续照护等必要背景仍可保留。

独立支持按每条实际结论检查：允许 OR 分支，也允许分别保留各自充分支持的重叠 Fact；
不要求枚举所有组合。具体属性需要额外上下文不算冗余，但不能只保存带额外属性的大句，
导致原本独立完整的结论丢失。必要的指代、对象、选项及否定前提不能机械删去。反过来，
无需这些前提也完整成立的结论，不应绑定其它消息。对当前四组开发样本，k3 对母亲经营
面包店的独立确认必须保留；v6 中用户不知道程越想去苏州的原因，无需 v2；h4 的告知
不能升级成 north 观测确实发生。以上分别检查漏抽、冗余依赖和断言升级，不能互相抵消。

每组记录首次结果、模型请求轮数、每次工具查询返回的 ID／新增信息、
输入输出 Token、缓存读写、耗时及供应商可确认的成本；缺失值标为未知。
基线与候选都使用相同记录方式。缓存合同变化单独标注，不能归因于
Prompt 语义改进。效率更好不能抵消内容错误。

候选必须覆盖全部必要信息，无错误归属或虚构，独立验收集无明确退步。
`source_quality` 的关键词脚本仅是抽取侧启发式筛查，不是本链路的评分器；
它不裁定措辞差异或完整链路是否通过。

最终分别报告已证实改善、仍有问题、成本变化、未覆盖项。真实模型未跑，
只能报告本地合同通过／待验收；只有可读性改善时明确说明。短样本不证明
真实 256K 压缩效果或长期质量稳定性。已用于开发或反复核对的样本不能继续称为 holdout；
当前四组均为开发集。历史报告与原始输出保留原文；使用本节统一判据重新评审时另存记录，
说明与旧判定的差异，不以更换评分口径宣称模型输出改善。
