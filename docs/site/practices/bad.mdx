---
title: Troubleshooting Memory Quality
---

Inspect the Fact operation receipt first, then the original flush Operation.

- If a Fact is missing or semantically wrong, compare the bounded input and its
  evidence associations. Fact extraction does not read old Facts or use profile
  categories as a filter.
- If Facts are correct but Profile/Event are stale, inspect maintenance status.
  A failed flush can be explicitly recovered without importing the messages again.
- Clarify Topic/Subtopic descriptions when profile organization is unsuitable.
  Do not use retired strict-mode, validation or Event-theme switches.
- Contradictory historical statements are intentional. Derived memory should keep
  temporal context and uncertainty instead of assuming latest ingestion is truth.
- Delete a message's memory contribution with source/message IDs and a stable
  idempotency key. Fact evidence changes synchronously; derived text can remain
  until maintenance succeeds. Deleting an Event is a separate operation.
