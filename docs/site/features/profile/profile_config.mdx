---
title: Profile Configuration
---

Profile categories guide the unified AgentLoop, not Fact extraction.
Facts keep supported historical statements even when they do not fit a profile
category. Contradictory statements can coexist; derived profiles use relevant
statements, time and explicit corrections without editing the Facts.

Use `additional_user_profiles` to extend the default Topics or
`overwrite_user_profiles` to replace them:

```yaml
overwrite_user_profiles:
  - topic: work
    description: Long-term professional background
    sub_topics:
      - name: company
        description: Employer, with temporal context where known
```

The loop stays inside the configured Topics and can create or reorganize
Subtopics. Profile entries retain Fact support. Model output validation and
ownership checks always apply.

The former `profile_strict_mode`, `profile_validate_mode` and nested
`validate_value` controls have been removed. Supplying them is an error;
there is no mode that disables evidence checks. See the
[configuration reference](/references/local_config) for supported settings.
