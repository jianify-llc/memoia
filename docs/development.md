# Development

The service code is `src/worker`. Cloudflare HTTP/Queue/Cron and Node HTTP/polling adapters call the same business functions. The public SDK is `sdks/typescript`; `src/mcp` is an optional local TypeScript client adapter.

## Local setup

Install Node.js 22, pnpm 10.12.4, Docker and PostgreSQL client tools. Install each package with `pnpm install --frozen-lockfile`. In the Worker package use `pnpm check`, `pnpm test`, `pnpm build` and `pnpm dev`. A dry-run build uploads nothing.

`pnpm build:node` bundles the Node API, maintenance worker and migration CLI with the same Prompt files and SQL migrations. Production Docker uses Node 24. Its Compose stack runs its own PostgreSQL/pgvector; Supabase/Hyperdrive remains the Cloudflare deployment path. See the [Docker setup](../deploy/README.md#docker-independent-postgresql) for explicit initialization and startup.

Explicitly supply local test database URLs. The complete root gate in [the deployment guide](../deploy/README.md) starts isolated PostgreSQL/Redis and runs every required integration test. Worker runtime uses Legato Task leases for execution ownership. Model waits hold no database transaction or checked-out connection. A running task renews its lease every 60 seconds. The lease expires 180 seconds after claim or the last successful renewal, capped by the slice's hard deadline.

## Configuration

Cloudflare Workers require a Hyperdrive binding with query caching disabled, including local Workers development. Node and Docker use an explicit `DATABASE_URL`. Worker secrets include `ACCESS_TOKEN`, `OPENAI_API_KEY` and any separate embedding/billing credential. `MEMOIA_CONFIG` supplies supported service settings as JSON; project settings override model, reasoning, language, topics and Fact-specific selection through the normal management API. Store sensitive gateway headers as secrets. No credentials belong in repository templates or logs.

Service configuration must be a JSON object with supported field names and valid types. Invalid configuration is rejected before accepting business work, including unknown/retired keys; diagnostics contain field names, not values. `source_input_retention_seconds` is a positive integer (default 604800): it governs temporary import input. Existing unexpired inputs keep their original expiry on retry; completion erases input immediately.

The embedding adapter is selected by service configuration: OpenAI (default `text-embedding-3-large`), Jina (`jina-embeddings-v4`) or Ollama. The [Jina v4 license](https://jina.ai/contact-sales/) permits research and non-commercial use. The database accepts 1536 dimensions, and `embedding_dim` may be omitted or set to 1536. Verify that the selected Ollama model returns 1536 values for both document and query input. Use one provider, model and document/query mode for each database. A credential or gateway change can reuse the index if it preserves that embedding space. Switching embedding spaces requires a separate reindex and cutover. Pause the old writers, regenerate the existing searchable vectors with the new model, and verify retrieval before enabling writers and queries with the new configuration.

Both AgentLoops use project model settings and attempt Flex before Standard within the same slice budget. Fact extraction runs per sealed Blob and keeps only its local draft/candidate as a checkpoint. Its SDK tool turns replay in invocation memory with `store: false`; its common prefix uses a 12h cache boundary and dynamic text uses implicit 30m caching. Profile/Event maintenance keeps complete instructions on the existing Responses chain, with the 12h boundary on new/rebuilt chains. Project context and Fact inputs are user data, separate from the fixed instructions. A checkpoint made with the previous input protocol restarts from current data through the existing recovery path. External Agents tracing stays off. Use numerical provider usage and controlled task identities to distinguish these requests. Maintenance can fall back to Standard immediately when waiting for Flex would reach the soft deadline. At the soft deadline the task yields at its next safe checkpoint. Event publication computes vectors before writing. Event body, evidence and vector use one standalone statement. The statement compares the existing Fact version row so a concurrent withdrawal cannot leave a newly published Event with stale evidence.

Stage receipt confirms temporary input. The caller seals a Source batch, and the queue completes Facts before the existing Profile/Event maintenance. Source deletion keeps its immediate Fact semantics. Task slicing uses a twelve-minute cooperative boundary and fourteen-minute hard boundary; safe state is checkpointed through Legato. Preserve original receipts on timeout or uncertain commit. See [API contracts](api.md), [migration and recovery](guide/typescript-worker-migration.md), and [test coverage](guide/ts-contract-coverage.md).

Node owns one bounded database pool per API/worker process (eight connections); individual invocations borrow it. Cloudflare invocations own and close their existing pools. The Node worker polls every five seconds with four execution slots and sweeps expired input every five minutes and expired usage daily. Both sweeps also run at startup. Polling and cleanup continue while slots are occupied. Queue notification reservations never block Node execution selection. SIGTERM stops intake and drains actual handler/slice promises before closing the pool. Compose allows sixteen minutes; forced termination preserves database task state and the last safe checkpoint for normal lease recovery, rather than claiming the interrupted work succeeded.

Platform adapters assemble the common Runtime. Only the Cloudflare adapter resolves Hyperdrive and implements the optional `MaintenanceWakeup.send` port with Queue; the Node adapter owns process resources and polling. Business code uses the port without reading Queue bindings. Both drivers share PostgreSQL task selection, notification receipts, leases and the maintenance consumer; no extra scheduler state or dummy Queue is introduced.

Dependency versions and security overrides live in package manifests/locks. The scoped esbuild override patches Drizzle's legacy loader without changing the ORM or migration format; validate it with isolated schema generation. SDK validator generation uses the locked AJV version and must preserve the OpenAPI contract when regenerated. Audit development tools separately from shipped production dependencies; an audit result does not establish model quality or deployment acceptance.

## Database statements and transactions

The rules below define the target for implementation and review. Verify each affected entry point against them.

- Use standalone, schema-qualified statements for probes, ordinary retrieval and independent writes. Retrieval uses ordinary `SELECT` statements without an explicit read transaction.
- Reuse rows and derived values already loaded by the same request. Read them again only when the next operation needs a newer committed value to enforce a business rule.
- Reject a response budget that cannot hold an empty result before reading candidates or requesting embeddings.
- Use PostgreSQL’s default isolation for short write transactions (normally READ COMMITTED). Open one only when dependent writes must commit together. For each explicit lock or transaction, identify the concrete failure it prevents and the business rule at stake. Prefer existing constraints and conditional writes.
- Use Legato's standalone claim for Fact and maintenance tasks, with the watchdog tracking execution ownership. Read the fixed batch after claiming. Never wrap an entire Queue task in a transaction. Release the transaction and checked-out connection before model calls (including Flex), embedding, Queue sends, other external I/O or retry waits.
- Bind vector writes directly to the typed destination column, which determines the parameter type and checks dimensions. Vector ranking explicitly qualifies the pgvector type and distance operator using the installed extension schema. These paths work without the extension in the connection search path.
- Fact import has one execution path. Append requests stage text and visual descriptions. A Fact flush claims the fixed inputs and runs the Fact Agent. Historical synchronous import receipts remain readable.
- Publish Profile and Event entries with their own version checks in standalone SQL. Profile history records only successful changes. Keep successful writes and resume the original Task for unfinished work. Confirm completion with the Legato CAS.
- Fact drafts, candidates, prepared vectors and segment failures update the append receipt in one conditional statement. The statement checks task ownership and the sealed input version, so a retired executor or a retracted input cannot save a stale checkpoint. Completed checkpoints are reused on recovery. Publishing new Facts, processing their message identities and completing the original receipts still commit together.
- Cron scans, notification reservation and acknowledgement, and retention cleanup use standalone SQL. The minute Cron only reconciles maintenance. The five-minute Cron clears expired operation input. The daily Cron removes expired usage counters. Daily history includes today and the previous 29 days, while the current calendar month counter supports quota checks. Expiry checks still apply at retry time. Blob sealing and expired lease revocation keep their concurrency protections.

## Database trace boundaries

`memoia.db.acquire` measures the Worker-side pg checkout. Hyperdrive can still open an origin connection while submitting `BEGIN`. `memoia.db.query` distinguishes BEGIN, statements, COMMIT and ROLLBACK, and preserves a valid PostgreSQL SQLSTATE before error translation. `memoia.db.deadline` records that the local database timer fired. Health checks and expired input cleanup have fixed operation names. These spans contain no SQL, parameter values, connection strings or database error text.

For a scoped Test investigation, set `MEMOIA_HEALTHCHECK_DB_TRACE=true` on the Test Worker when deploying. The value defaults to off. The health endpoint normally sends one `SELECT 1`. With diagnostics enabled, it instead sends one statement that reads its PostgreSQL backend PID and start time, and records them only in the internal HTTP Span. The health response still exposes only status. An origin connection rejection (`53300`) at checkout, BEGIN, or a standalone statement yields a retryable `503 database_unavailable`. Requests with earlier committed steps continue through the original Operation receipt. The HTTP Span marks returned 5xx responses as errors.
