# TypeScript contract coverage

This is an inventory of behavioral evidence for the Python-to-Worker transition, not a claim that every legacy assertion was ported. The legacy suite was inspected from the pre-removal snapshot. PostgreSQL fixtures require the isolated test database; fake model transports and pure tests do not establish live-provider or production behavior.

| Legacy business area (Python test files) | TypeScript evidence | Remaining boundary |
| --- | --- | --- |

Full corpus and live-model quality remain unverified. |

`*.fixture.ts` files are loaded by their corresponding top-level test; PostgreSQL cases are skipped without the required test database. Tests above document contracts present in the suite, not a record that they passed on a particular candidate. Check the current test run separately.

Focused parity regressions additionally cover a 1,000-message already-processed import using batch identity reads, fixed input expiry and configurable cleanup (`facts-integration`); more than 1,000 associated entries ranked and capped in SQL before evidence hydration (`retrieval-bounded`); and shared service-config validation, nullable legacy settings and value-free errors (`service-config`). These are deterministic database/request-contract checks, not live retrieval-quality measurements.

Docker/Node adapter regressions add real HTTP authentication and shutdown/port-conflict behavior (`node-api`), packaging of both executors and migration resources (`node-build`), borrowed/owned pool lifecycle (`runtime-lifecycle`), and PostgreSQL polling, notification-reservation independence, user exclusivity, saved-checkpoint continuation and in-flight drain (`node-worker-pg`). Existing `maintenance-recovery` remains the common slice, lease and unknown-commit evidence. A new Runtime instance is not an OS restart; actual process/container recovery must be recorded separately when exercised.
